What it does, and what protects it

A small password manager built around a few plain decisions rather than a long feature list.

Encrypted at rest

Saved passwords and notes are stored as Fernet tokens (AES with an HMAC). The database never contains a readable password.

A key for every user

Each account gets its own encryption key, derived from a server secret and a per-user salt. One user's key can't open another's data.

Reveal on request

The vault list only ever contains masked dots. A password is decrypted for a single request when you press Reveal, then hidden again.

Real randomness

The generator uses the operating system's secure random source and guarantees each character type you ask for appears.

Guarded sign-in

Hashed login passwords, CSRF tokens on every change, rate limiting, temporary lockout, and identical error messages for unknown users and wrong passwords.

Health checks

Spot weak, reused and stale passwords. Reuse is detected on the server, so plaintext never reaches the browser to do it.

How it works

Make an account

Choose a strong login password (12+ characters). It's hashed with scrypt and never stored as text.

Generate or add

Let PassVault generate a password, or type your own. Either way it's encrypted before it touches the database.

Find and use

Search the vault, reveal or copy a password when you need it. The clipboard is cleared after a short delay.

Security architecture

Two separate paths. Your login password is never used as an encryption key.

Signing in

  1. login password
  2. scrypt hash (Werkzeug)
  3. users.password_hash

One-way. Even PassVault can't recover your login password.

Saving a credential

  1. site password
  2. Fernet, per-user key (HKDF)
  3. vault_items.encrypted_password

Reversible on purpose, because you need the password back. The key lives in .env, not in the database.

This is a self-hosted app, not an audited product. Whoever controls the server's .env and database can decrypt vault data, and a compromised browser can still read what you reveal. The README spells out the model and its limits.
